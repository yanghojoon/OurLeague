# 로그인 후 프로필 등록

구현일: 2026-11-17. Apple 로그인 다음 단계로 닉네임 등록과 기존 프로필 복구를 연결했다. DB 스키마와 테스트 데이터는 변경하지 않았다.

## 화면 흐름

```text
유효한 로그인 세션
  └─ 본인 profiles 조회
      ├─ 프로필 있음 → 내 동호회 목록
      ├─ 프로필 없음 → 닉네임 입력 → 저장 성공 → 내 동호회 목록
      └─ 조회 실패 → 오류 및 재시도 (신규 가입으로 처리하지 않음)
```

- 기존 로그인 화면의 녹색 강조색과 시스템 글꼴을 유지한다. 저장 중에는 입력과 중복 요청을 막고 진행 상태를 표시한다.
- 저장 실패 시 닉네임 입력을 유지하고 다시 시도할 수 있다. 실패나 로그아웃으로 취소된 작업의 늦은 응답으로 앱에 진입하지 않는다.
- 로그인 계정이 바뀌면 루트의 계정 ID 기반 화면 식별자로 이전 프로필 상태와 탐색 스택을 제거한다.

## 데이터 계약과 보안

- 조회: `profiles`에서 `id,display_name`을 선택하고 로그인 계정 UUID로 필터링한다. 0건만 신규 프로필로 취급하고 네트워크·권한·디코딩 오류는 재시도 상태로 구분한다.
- 저장: [Supabase Swift RPC](https://supabase.com/docs/reference/swift/rpc)로 기존 `league_command`를 호출한다. 인자는 `operation: save_profile`, `payload: {display_name: ...}`, `request_id: UUID`이다.
- 사용자 ID를 저장 payload에 넣지 않는다. 서버는 `auth.uid()`를 기준으로 본인 프로필을 저장한다. 클라이언트도 저장 직전 세션과 조회·저장 응답의 계정 ID를 확인한다.
- 저장 응답은 프로필 전체가 아닌 `{id}`이다. 서버 확인 후 해당 ID와 전송한 닉네임으로 프로필 상태를 만들며 다음 실행 때 DB에서 다시 읽는다.
- 닉네임은 앞뒤 공백·줄바꿈을 제거한 뒤 **1~40 Unicode scalar**로 검사한다. DB의 `char_length` 기준에 맞추므로 여러 scalar로 구성된 이모지·결합 문자는 화면상 한 글자여도 여러 자로 계산될 수 있다. 게스트 닉네임의 별도 규칙과 혼용하지 않는다.
- 닉네임 중복은 허용한다. 사용자 식별은 UUID이며 기존 클럽 명단에 이름으로 자동 연결하지 않는다.
- 동일 닉네임 재시도에는 화면이 유지되는 동안 같은 `request_id`를 재사용한다. 입력이 바뀌면 새 ID를 사용한다. 서버의 기존 command receipt가 동일 명령의 중복 처리를 방지한다. 앱 종료 후까지 미완료 요청을 저장하는 기능은 없다.
- 관리자 키나 사용자 메타데이터를 권한 판단에 사용하지 않는다. `profiles`의 실제 SELECT 정책은 `authenticated`이면서 `id = auth.uid()`이며, 익명 역할에는 SELECT 권한이 없다.

## 검증

- 기존 XCTest 파일에 프로필 회귀 검사 15개를 추가했다: 기존/누락 프로필, 조회 실패와 재시도, 설정 오류, 다른 계정 응답 거부, 닉네임 정규화·길이·RPC JSON 계약, 저장 완료 전 진입 방지, 중복 요청 방지, 재시도 ID, 작업 취소.
- 로컬 Foundation·Combine·CryptoKit·Security 계약 실행으로 기존 검사 포함 43개를 확인한다. 이 실행은 XCTest 러너나 실제 Supabase SDK 통합 테스트를 대체하지 않는다.
- 실제 프로젝트의 RLS, 익명/인증 역할 권한, 프로필 길이 제약을 읽기 전용 SQL로 확인했다. 검증을 위해 실제 사용자 프로필을 생성하거나 변경하지 않았다.
- 2026-11-24에 실제 Xcode 설치를 확인하고 [시뮬레이터 XCTest·로그인 UI 검사](xcode-verification.md)를 통과했다. 이전 Xcode 미설치 판단은 CLI 경로만 확인한 오류였다. 실제 로그인 후 프로필 저장 왕복, 인증된 세션 복구, 오프라인 재시도, 로그아웃 및 계정 전환은 기기에서 추가 확인해야 한다.

## 남은 범위

2026-11-24에 후속 [동호회 조회·생성·선택](supabase-clubs.md)을 연결했다. 프로필 수정 화면, 계정 삭제, 동호회 가입 및 실제 경기 데이터 연동은 별도 단계이며 PRD 전체가 완료된 것은 아니다.
