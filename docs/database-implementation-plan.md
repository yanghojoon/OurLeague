# PRD v0.3 데이터 모델 반영 계획

기준: `OurLeague-MVP-PRD-v0.3.html` 4·6~11·13절. 범위는 DB 모델, DB 권한·원자적 저장 경계, Swift 행 모델과 검증이다. 앱 화면·인증 공급자 설정·게스트 웹 배포는 포함하지 않는다.

1. 기존 대문자 테이블과 데이터를 삭제하지 않고 보존한다. 새 UUID 기반 정규화 테이블을 별도로 만든다.
2. 계정과 동호회별 소속·참가자를 분리한다. 모임·참석자·코트·경기·선수·결과·정정 이력·초대·게스트 세션을 추가한다.
3. 조회는 승인된 클럽 소속에 대한 RLS로 제한한다. 쓰기는 권한 검사·모임 단위 잠금·버전 검증을 수행하는 RPC로 한정한다. 토큰과 재시도 기록은 비공개 스키마에 둔다.
4. 외래키·유일성·CHECK·지연 제약 트리거로 네 명/두 팀, 소속 일치, 코트·선수 중복, 완료 결과 일관성을 검증한다.
5. 기존 연결 관계가 명확한 기록만 DB 안에서 변환한다. 알 수 없는 운영자·시각·코트·라운드는 추측하지 않는다. 운영자 미지정 클럽과 검토 필요한 모임은 잠긴 이관 상태로 유지한다.
6. 클럽별 유효한 완료 결과만 승패에 집계한다. 중단은 출전 횟수에만 포함한다. 전적이 없으면 승률은 NULL이다.
7. SQL 회귀 검증은 트랜잭션 후 ROLLBACK하여 실제 사용자 데이터와 분리한다. 비소속 접근 거부, 다중 소속, 중복·무결성·재시도·정정·게스트 범위를 확인한다.
8. 원격 마이그레이션, 데이터 보존 건수, 보안/성능 Advisor와 Swift 타입 검사를 확인하고 실제 적용 범위와 남은 설정을 기록한다.

현재 확인된 이관 전 건수: Club 1, Player 14, Club_Participants 14, GameByDay 1, Game 3. Auth 계정 0개이므로 기존 클럽의 운영자를 임의 지정하지 않는다. 승리팀을 판정할 수 있는 기존 경기는 2개다.
