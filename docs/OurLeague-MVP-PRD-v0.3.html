01

제품 정의

첫 출시에서는 한 동호회의 모임을 준비하고 마무리하는 문제를 해결합니다.

사용자의 문제 문제 가설

  • 채팅으로 받은 참석 정보를 따로 모아 대진에 옮겨야 합니다.
  • 코트와 인원이 바뀌면 누구는 많이 뛰고 누구는 오래 쉬게 됩니다.
  • 게스트에게 앱 가입을 요구하면 참석 확인이 번거로워집니다.
  • 모임이 끝난 뒤 결과가 흩어져 개인별 전적을 확인하기 어렵습니다.

제공할 가치

운영자는 참석 명단을 확정하면 대진을 얻고, 결과만 남기면 전적이 쌓입니다.

게스트는 공유 링크에서 닉네임과 참석 여부를 제출하고, 승인 후 그 모임의 대진과 결과를 확인합니다.

대표 사용 시나리오: 운영자 1명이 6~16명의 복식 테니스 모임을 준비하고, 게스트를 포함한 참가자의 경기 횟수와 승패를 관리합니다.

용어를 먼저 구분합니다

동호회 · Club명단과 모임 히스토리가 쌓이는 지속적인 그룹.
모임 · Session특정 날짜·장소의 테니스 일정. 사용 가능한 코트와 여러 경기를 포함합니다.
경기 · Match네 명이 참여하는 한 번의 복식 승부. 통계의 기본 단위입니다.
코트 · Court경기가 실제 진행되는 한 면. 모임에 코트 수와 식별용 이름을 설정합니다.
라운드 · Round여러 코트에서 동시에 진행할 수 있도록 생성한 대진 묶음. 각 경기는 코트에 배정됩니다.

이 문서에서 “게임 생성”은 모임 생성과 그 안의 경기 대진 생성으로 나눕니다. 테니스 점수의 game·set과 제품의 Match를 혼동하지 않습니다.

02

목표와 성공 기준

개발 완료와 제품 가치 검증을 서로 다른 기준으로 판단합니다.

운영 시간 줄이기

명단 확정부터 첫 대진 확정까지 걸리는 시간을 줄입니다.

5분 이내

실제 운영자가 도움 없이 완료.
명단 확정 후 대진 확정까지.

가입 장벽 없애기

게스트가 앱 설치·계정 가입 없이 참석 신청을 완료합니다.

80% 이상

유효 초대 페이지 방문 중 참석 응답 제출 비율. 불참 응답도 포함.

다음 모임에도 사용

한 번의 대진 도구에서 동호회의 반복 운영 도구로 이어집니다.

2회 이상

파일럿 동호회 3곳 중 2곳이 4주 이내 서로 다른 모임을 2회 완료.

모든 수치는 초기 검증 목표입니다. 출시 기술 기준은 16절의 P0 수용 기준 통과이고, 위 전환·재사용 지표는 출시 직후 4주 동안 관찰합니다. 표본이 작으므로 관찰 건수와 비율을 함께 기록합니다.

최소한의 측정 설계

session_created → roster_confirmed → schedule_confirmed → match_result_saved → session_completed

valid_invite_viewed → guest_response_submitted → guest_approved

모임·브라우저 세션 단위로 중복 제거합니다. 개인정보·초대 토큰·닉네임을 분석 이벤트에 넣지 않습니다. 초대 만료·봇 프리뷰는 방문 분모에서 제외합니다. 초기에는 최소 이벤트 저장과 운영자 인터뷰로 충분하며 별도 분석 대시보드는 만들지 않습니다.

사용자와 권한

로그인 계정, 동호회 명단, 해당 모임의 게스트는 서로 다른 개념입니다.

역할주요 행동조회 범위제약

동호회 생성자		동호회·명단 관리, 참석 승인, 대진 확정, 결과 입력·정정, 초대 폐기해당 동호회의 명단·모임·개인 전적MVP는 동호회당 운영자 1명. 한 계정이 여러 동호회의 운영자일 수 있음. 해당 동호회 운영자 탈퇴 시 인계 또는 동호회 종료 필요.

모임 게스트

초대 링크 방문자
아직 승인되지 않은 사람		모임 안내 보기, 참석 신청공유된 모임의 일정·장소·안내만기존 참가자 목록·대진·결과는 미노출. 승인받은 브라우저 권한 필요.

한 계정, 여러 동호회 확정

한 사람은 여러 클럽에 동시에 가입할 수 있습니다. 새 동호회에 가입해도 기존 동호회 소속을 유지합니다. 동호회별 가입 승인 상태와 역할은 독립적으로 관리합니다.

같은 로그인 계정가입 상태·역할가능한 행동
동호회 A승인 · 운영자A의 명단·모임·대진·결과 관리
동호회 B승인 · 회원B의 모임·전적 조회와 자기 참석 응답
동호회 C가입 승인 대기자기 가입 상태 확인. C의 내부 정보 조회·수정 불가
  • “내 동호회”에서 가입한 동호회 목록과 자기 역할을 확인하고 전환합니다. 선택한 동호회가 모임·명단·전적 화면의 조회 범위입니다.
  • 동일 계정의 중복 소속을 막는 범위는 동일 동호회 안입니다. A와 B에 각각 소속되는 것은 허용하고 A에 소속 기록을 두 개 만들지는 않습니다.
  • A의 운영자 권한이 B로 넘어가지 않습니다. 서버는 각 요청의 대상 동호회에 대한 소속·역할을 확인합니다.
  • 전적과 참가자 기록은 동호회별로 분리합니다. 같은 계정에 연결된 A·B의 전적도 자동 합산하지 않습니다. 전체 클럽 통합 개인 전적은 후속 범위입니다.
  • 동호회 탈퇴·비활성화는 해당 동호회에만 적용합니다. 계정 삭제는 모든 소속의 계정 연결·권한 제거와 별도 개인정보 삭제 정책을 적용합니다.
회원 가입 초대와 모임 게스트 초대를 구분합니다. 회원은 iOS에서 로그인 후 동호회 가입을 신청하고 운영자가 승인합니다. 게스트 링크는 해당 모임에만 적용됩니다. Android 사용자는 첫 출시에서 게스트 웹으로 참여할 수 있으며, 회원용 전체 기능은 iOS에서 제공합니다.
05

핵심 사용자 흐름

앱과 웹을 연결하는 하나의 운영 사이클.

A. 운영자: 모임을 열고 기록까지 마무리

STEP 01동호회 준비

로그인 → 동호회 생성 → 정기 참가자 등록 또는 회원 가입 승인.

STEP 02모임과 참석 확정

일시·장소·코트 입력 → 참가자 지정 → 초대 공유 → 게스트 승인.

STEP 03대진 확정·진행

라운드 수 선택 → 대진 생성 → 횟수 확인·수정 → 경기 시작.

STEP 04결과와 히스토리

경기별 승리팀 기록 → 미완료 경기 처리 → 모임 완료 → 전적 확인.

출시 검증에서는 운영자가 다른 메신저로 참석을 재취합하거나 별도 스프레드시트에 결과를 옮길 필요가 없는지 확인합니다.

B. 게스트: 가입 없이 참여

STEP 01공유 링크 열기

Safari·Chrome 등 모바일 브라우저에서 모임 일정과 안내 확인.

STEP 02참석 응답

닉네임·참석 여부 제출 → “승인 대기” 표시. 이메일·전화번호 필수 입력 없음.

STEP 03참여 승인

운영자가 신청을 확인 → 승인된 브라우저에서 대진 조회. 새로고침으로 확인.

STEP 04당일·이후 확인

내 경기와 모임 결과 확인. 참여 권한 만료 후 운영자에게 새 링크 요청.

대진 생성 규칙

참가 기회의 균형을 우선하고, 대진의 다양성과 실력 균형은 차례로 확장합니다.

반드시 지킬 제약 P0

  • 경기당 승인 참석자 네 명, 2명씩 두 팀.
  • 같은 참가자가 같은 라운드의 다른 코트에 중복 출전하지 않음.
  • 한 라운드 경기 수는 사용 가능 코트 수를 넘지 않음. 라운드마다 코트당 최대 한 경기 배정.
  • 실제 진행 중 경기에도 코트·참가자 중복 금지. 라운드 번호가 달라도 동시에 같은 사람이나 코트를 사용할 수 없음.
  • 불참·미승인·비활성 참가자를 배치하지 않음.
  • 시작·완료 경기는 재생성으로 변경하지 않음.
  • 참가자 ID, 명단 버전, 대진 버전, 생성 seed를 기록.

최적화의 우선순위

  1. P0 · 참가 횟수 차이 최소화. 동일 조건일 때 최대·최소 차이 ≤1을 목표로 검증.
  2. P1 · 연속 휴식 완화. 횟수 균형을 해치지 않는 범위에서 적용.
  3. P1 · 파트너·상대 반복 완화. 가능한 대진 사이의 비교 기준.
  4. 후속 · 성적 기반 팀 균형. 데이터 확보 후 별도 레이팅 정책 정의.

네 명만 참석하는 경우처럼 다양성을 만들 수 없는 조건에서는 반복을 허용합니다. 실력 입력이나 성별 조건을 첫 대진의 필수 입력으로 요구하지 않습니다.

“동일 횟수”의 정확한 의미

N명, C면, R라운드에서 매 라운드 최대한 코트를 사용하는 기본안입니다. 참석자 전원이 처음부터 끝까지 가능하고 코트 조건이 같다고 가정합니다.

K = min(C, floor(N / 4)) · 라운드당 경기 수
M = K × R · 전체 경기 수
A = 4 × M · 전체 출전 슬롯
개인별 목표 = floor(A / N) 또는 ceil(A / N)
모두 같은 횟수가 되기 위한 필요조건 = A mod N = 0

정수 계산은 총량의 필요조건과 목표 범위입니다. 실제 대진의 성립 여부는 중복 출전·명단 제약을 포함해 검증해야 합니다. 참가자가 많고 라운드가 적으면 목표 최소가 0일 수 있으므로, 대진 확정 전 “경기 없는 참가자”와 필요한 추가 라운드 수를 보여줍니다.

검증 가능한 예시: 6명 · 1면 · 3라운드

라운드팀 A팀 B휴식
1A · BC · DE · F
2A · EB · FC · D
3C · ED · FA · B

A~F가 모두 2경기씩 참여합니다. 반면 5명·1면·3라운드는 12개 출전 슬롯이므로 2명은 3경기, 3명은 2경기가 됩니다.

모임 장소에 코트가 2면이면 서로 다른 8명이 2경기를 동시에 진행할 수 있습니다. 코트 수는 동호회 고정값이 아닌 모임별 사용 가능 면수입니다. 한 장소의 여러 코트를 기본 범위로 하며 여러 장소의 이동·시간표 최적화는 후속으로 둡니다.

코트별 진행 정책 제안

  • 운영자는 코트별로 경기 시작·완료·결과를 관리합니다. 코트 1이 완료되어도 코트 2는 진행 중일 수 있습니다.
  • 라운드는 대진 배치를 위한 묶음입니다. 전체 코트의 일괄 종료를 강제하지 않고, 해당 코트가 비어 있고 배정된 네 명 모두 다른 경기 중이 아니면 코트별 다음 경기를 시작할 수 있습니다.
  • 다음 경기는 해당 코트의 라운드 순서대로 진행. 네 명 중 누군가 다른 코트에서 경기 중이면 시작을 차단하고 해당 참가자와 대기 사유를 표시합니다. 자동 순서 최적화·경기 재배정은 후속 범위입니다.
  • 경기 시작 시 서버가 코트와 네 참가자의 사용 여부를 한 번에 검사·확정합니다. 다른 기기의 동시 시작 요청도 한쪽만 허용하고 최신 진행 상태를 반환합니다.
  • 코트 수 감소·증가는 경기 시작 전에만 허용합니다. 이미 확정된 대진은 갱신 필요로 표시하고 코트 배정·출전 횟수를 다시 계산해 재확정합니다.

수집·응답·승인

  • 필수 정보는 닉네임(제안 2~20자)과 참석 여부. 전화번호·이메일·실력은 기본 수집하지 않음.

  • 참석 신청은 운영자 승인 후 정원에 포함. 불참은 응답으로 저장하지만 대진에서 제외.
  • 승인과 정원 증가는 하나의 트랜잭션. 두 요청이 마지막 자리를 동시에 승인받지 못함. 대기열 자동 승급은 후속.

링크와 브라우저 권한

  • 공유 URL에는 추측하기 어려운 모집 토큰. 서버에서 해시를 보관하고 모임·만료·폐기 상태 확인.
  • 제출 후 해당 신청만 관리하는 브라우저 세션 발급. 모집 URL만 알아서는 승인자의 신원을 사용할 수 없음.
  • 모집 토큰은 참석 마감, 모임 취소·완료, 운영자 폐기 중 가장 빠른 시점에 닫힘.
  • 승인 게스트 조회 세션은 모임 종료 예정 시각 + 7일 만료 제안. 즉시 차단이 필요하면 운영자가 개별 승인 권한 폐기.
  • 모집 링크 재발급은 기존 모집 토큰을 폐기. 이미 승인된 게스트 세션은 별도로 유지·폐기하며 그 차이를 운영자에게 표시.
  • 브라우저 데이터 삭제·새 기기에서는 본인 권한 자동 복구 불가. 운영자 재확인 후 개인 링크 재발급. 이메일 기반 자동 복구는 후속.
기술 방식은 미확정입니다. 서버가 발급하는 제한된 게스트 세션 또는 익명 Auth 계정과 명시적 참가 승인 관계로 구현할 수 있습니다. 익명 인증이 성공했다는 사실만으로 회원 권한을 주지 않습니다. Supabase의 익명 사용자는 DB의 authenticated 역할을 가지므로 실제 동호회 소속·게스트 승인 범위를 확인해야 합니다. [2]

결과와 전적 정책

불완전한 점수와 중복 저장으로 전적이 틀어지지 않도록 최소 규칙을 정합니다.

기록 단위와 집계

  • 경기 완료: 승리팀을 확정한 Match 한 건. 네 명 모두 개인 경기 수 +1, 승리팀 두 명 승 +1, 패배팀 두 명 패 +1.
  • 중단: 실제 출전 횟수에는 포함하되 승패 통계에서는 제외. 미시작 취소는 출전·승패 모두 제외.
  • 승률: 승 / (승 + 패) × 100. 정수 반올림 제안. 분모 0이면 “—”. 무승부·기권승은 첫 출시에서 별도 처리하지 않음.
  • 조회: 동호회별 전체 기간 개인 전적과 최근 경기 목록. 모임 중 저장된 완료 결과도 즉시 반영하며 모임 취소가 기존 완료 경기 결과를 지우지 않음.
  • 범위: 복식 개인 전적. 파트너 조합별 통계, 전체 동호회 통합 랭킹·개인 글로벌 전적은 후속.

정정과 동일인 관리

  • 운영자만 결과 정정. 이전 결과, 새 결과, 사유, 수정자, 시각을 보관하고 같은 기록이 두 번 집계되지 않도록 처리.
  • 참가자·팀 구성은 경기 시작 시 고정. 입력 오류로 이미 완료된 경기의 구성까지 바꿔야 하면 운영자가 결과 무효화 사유를 남기고 수정된 경기 기록을 생성.
  • 계정과 무관한 안정적인 참가자 ID를 기록. 닉네임 변경은 승패 ID에 영향 없음.
  • 모임 한정 게스트는 기본적으로 모임마다 별개 기록. 정기 참가자에 운영자가 명시적으로 연결한 경우에만 동호회 전적이 이어짐.
  • 계정 연결·기존 게스트 기록 통합은 신원 확인 및 중복 경기 검사가 필요. 자동 병합·일괄 병합 UI는 MVP 제외.
데이터 삭제 제안: 계정 삭제 시 인증 정보·프로필·연결 개인정보·게스트 세션을 삭제 또는 폐기합니다. 공동 경기 기록을 유지할 경우 재식별 가능한 닉네임·계정 연결을 제거해 “삭제된 참가자”로 표시합니다. 삭제·보존 범위와 보관 기간은 W1에 확정하고 개인정보 처리 안내와 실제 동작을 일치시킵니다. 단순 계정 비활성화로 탈퇴를 완료했다고 표시하지 않습니다. [7]
